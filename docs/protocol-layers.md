# Protocol Layers

> **Positioning note (2026-10-19).** This page is a technical reference for every layer, including the extension layers (registry discovery, orchestration). Aroha now describes itself as the protocol for **bounded, verifiable agent authority** — who is acting, what a person allowed, how to stop it, and what happened. Discovery, sagas, settlement and commerce remain available as optional extensions and are documented here as such. See [What Aroha is (and is not)](positioning.md).

Detailed reference for each of Aroha's six layers.

---

## Layer 0 — Transport

**Package:** `@aroha-sdk/core` (`ArohaServer`, `ArohaClient`)

Every Aroha agent MUST expose three HTTP endpoints:

| Method | Path | Purpose |
|--------|------|---------|
| `GET` | `/.well-known/aroha-agent.json` | DID Document |
| `POST` | `/aroha/v1` | Inbound message endpoint |
| `WS` | `/aroha/stream?cid=<id>` | Async streaming |

*(If hosting a credential registry using `@aroha-sdk/credentials`, additional `/aroha/credentials` endpoints are exposed).*

**Security requirements:**

- Production: TLS 1.3+, mTLS recommended for providers
- Development: HTTP permitted only for `localhost`

## Layer 1 — Identity

**Package:** `@aroha-sdk/core` (`generateDID`)

*(For Human Credentials and RBAC, see the `@aroha-sdk/credentials` extension).*

### DID format

```
did:aroha:<unique-id>
```

Generated by `generateDID(id, endpoint)`. Returns an Ed25519 keypair and a signed DID Document.

### DID Document (served at `/.well-known/aroha-agent.json`)

```json
{
  "@context": ["https://www.w3.org/ns/did/v1", "...ed25519-2020/v1"],
  "id": "did:aroha:my-agent",
  "verificationMethod": [{
    "id": "did:aroha:my-agent#key-1",
    "type": "Ed25519VerificationKey2020",
    "controller": "did:aroha:my-agent",
    "publicKeyMultibase": "z<base58btc-32-bytes>"
  }],
  "authentication": ["did:aroha:my-agent#key-1"],
  "service": [{
    "id": "did:aroha:my-agent#aroha",
    "type": "ArohaEndpoint",
    "serviceEndpoint": "https://my-agent.example.com/aroha/v1"
  }]
}
```

### Trust levels

| Level | Requirements |
|-------|-------------|
| 0 | None — can read manifests |
| 1 | On-chain registration + minimum stake |
| 2 | Verifiable Credential from recognized trust anchor |
| 3 | Reputation score ≥ 8000 / 10000 |
| 4 | Explicit user authorization token |

*(RBAC roles are enforced by the `@aroha-sdk/credentials` extension, which defines roles such as `human:admin`, `human:user`, `agent:orchestrator`, etc. See [packages/credentials.md](packages/credentials.md) for details.)*

## Layer 2 — Registry

**Package:** `@aroha-sdk/registry` (`ArohaHttpRegistry`, `ArohaRegistryContract`, `ArohaDiscovery`, `ArohaIpfsClient`)

### Agent Record

```typescript
interface AgentRecord {
  didHash: string;          // keccak256(did) — privacy-preserving
  ownerAddress: string;     // operator's Ethereum address
  manifestCID: string;      // IPFS CID of capability manifest
  publicKeyB64: string;     // base64url Ed25519 public key
  stakedWei: bigint;        // stake (on-chain registry only)
  reputationScore: number;  // 0–10000, updated by oracle
  active: boolean;
}
```

### Capability Manifest (hosted on IPFS)

```json
{
  "aroha": "1.0",
  "did": "did:aroha:my-agent",
  "name": "Flight Booking Agent",
  "version": "1.0.0",
  "endpoint": "https://my-agent.example.com/aroha/v1",
  "protocols": ["aroha/1.0"],
  "capabilities": [
    {
      "id": "search-flights",
      "sagaRole": "none",
      "requiredTrustLevel": 1,
      "pricing": { "model": "free" }
    },
    {
      "id": "book-flight",
      "sagaRole": "participant",
      "reserveCapabilityId": "book-flight",
      "cancelCapabilityId": "book-flight",
      "requiredTrustLevel": 2,
      "pricing": { "model": "per-transaction", "fee": 2.50, "currency": "USD" }
    }
  ],
  "signature": "<base64url-Ed25519>"
}
```

### IArohaRegistry interface

All registry implementations share this interface:

```typescript
interface IArohaRegistry {
  register(did, manifestCID, publicKey, options?): Promise<void>;
  deactivate(did): Promise<void>;
  updateManifest(did, newCID): Promise<void>;
  resolveByDID(did): Promise<AgentRecord | null>;
  queryByCapability(capabilityIds): Promise<AgentRecord[]>;
}
```

## Layer 3 — Messaging

**Package:** `@aroha-sdk/core` (`buildEnvelope`, `validateEnvelope`)

### Envelope format

```json
{
  "@context": ["https://aroha-labs.com/contexts/v1", "...ed25519-2020/v1"],
  "id": "urn:uuid:<uuid-v4>",
  "type": "ArohaRequest",
  "from": "did:aroha:orchestrator",
  "to": "did:aroha:provider",
  "created": "2026-04-23T10:00:00Z",
  "expires": "2026-04-23T10:05:00Z",
  "nonce": "<random-hex-32>",
  "correlationId": "<saga-or-session-id>",
  "body": { "capability": "search-flights", "params": { "origin": "LHR" } },
  "proof": {
    "type": "Ed25519Signature2020",
    "created": "2026-04-23T10:00:00Z",
    "verificationMethod": "did:aroha:orchestrator#key-1",
    "proofPurpose": "authentication",
    "proofValue": "<base64url-Ed25519>"
  }
}
```

### Validation rules

`ArohaServer` validates every inbound message:

1. `proof.proofValue` must be a valid Ed25519 signature over the canonical envelope body (keys sorted, `proof` omitted)
2. `nonce` must not have been seen before (5-minute window)
3. `expires` must be in the future
4. `to` must match the receiving agent's DID

## Extension — Orchestration (formerly Layer 4)

> Specified in the [extensions document](spec/extensions.md) §1. `@aroha-sdk/orchestrator` is developed in `ArohaLabs/aroha-extensions`.

**Package:** `@aroha-sdk/orchestrator` (`SagaEngine`, `AgentSelector`, `Negotiator`)

### Saga execution

```typescript
const result = await saga.execute([
  { agentDID, agentEndpoint, capability: "book-flight", params, holdDurationMs: 300_000 },
  { agentDID, agentEndpoint, capability: "book-hotel",  params, holdDurationMs: 300_000 },
]);
```

**Phase 1 — Reserve (parallel):** All participants receive `ArohaReserve` simultaneously.
If any fails, skip to Phase 3.

**Phase 2 — Commit (sequential):** Each `ArohaCommit` is sent in order.
If any fails, go to Phase 3 in reverse order.

**Phase 3 — Compensate (LIFO):** `ArohaCancel` sent to every committed participant
in reverse commit order. Guarantees no partial state.

### Agent selection

```typescript
const selection = await selector.select(
  capability,
  params,
  discoveredAgents,   // from ArohaDiscovery
  { scores }          // from preference scoring
);
```

The selector fans out `ArohaRequest` to all eligible agents, collects responses,
scores them by price / reputation / preference fit, and returns the winner.

## Extension — Preference Context (formerly Layer 5)

> Specified in the [extensions document](spec/extensions.md) §2.

**Package:** `@aroha-sdk/preferences` (`createDefaultProfile`, `applySatisfactionSignal`)

Optional context carried in the `body.preferenceContext` field of any request:

```typescript
interface PreferenceContext {
  budget?: { max: number; currency: string };
  quality?: { minRating?: number };
  accessibility?: Record<string, boolean | string>;
  constraints?: string[];
  consentToken?: string;  // signed VC granting access to this context
}
```

After each saga, the orchestrator records a satisfaction signal that updates
the preference profile for future agent selection:

```typescript
const updated = applySatisfactionSignal(profile, {
  sagaId, agentDID,
  outcome: "satisfied",
  dimensions: { price: "satisfied", quality: "neutral", speed: "dissatisfied" }
});
```
